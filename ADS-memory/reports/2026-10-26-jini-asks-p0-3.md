# Jini asks from Open Marketing (P0-3), 2026-10-26

Filed by open-marketing-f8 with tovu-e1, the Jini coordinator. Both are **additive and opt-in**: existing Tovu behaviour is unchanged. OM consumes them only once published.

## 1. user-management: instance-injected permission catalog
**Today:** `@jini-ai/user-management` core keeps `permissionCatalog` as a module singleton (`packages/user-management/src/core/permissions.ts`). It is extended through the global `registerPermission()` and has no unregister/reset.

**Problem for OM:** the OM engineering contract forbids module singletons and append-only global registries. Every registry must be an injected instance that supports unregister/reset/dispose. So OM's approver identity stays on a `local_token` fallback instead of using user-management (P0-2b).

**Ask:**
- `createPermissionCatalog({ initial })` returns an instance with `register`, `unregister`, `has` and `list`.
- The server factories that validate grants or authorize (`login`/`validateSession`/`authorize`/seed, `buildIdentityRegistrations`) accept an optional `permissionCatalog` instance. When it is omitted, they keep using the current singleton.
- Plugins/features register their permissions on the instance at composition.

**Acceptance:** two catalogs in one process don't see each other's permissions. With no injection, behaviour is identical to 0.6.12.

## 2. outbox: due time (`availableAt`) on enqueue
**Today:** an OM job's enqueue time is its due time. OM added a bounded explicit due time in its own jobs slice (P0-2d, commit 124d607), because the outbox needs it for scheduled work such as recurring alert evaluation and delayed retries.

**Ask:**
- Jini outbox enqueue (including the coming 0.6.15 `enqueueWithReceipt`) accepts an optional `availableAt`, defaulting to the injected clock's now.
- It is validated: explicit `null` fails, and past and zero values are allowed.
- It is persisted, and claim never returns a job before its `availableAt`.
- Add cases to the conformance suite (`fencedOutboxConformance`): future job not claimable, becomes claimable at due time, ordering by due time.

**Acceptance:** OM can delete its local due-time handling when it swaps to the Jini outbox, with no behaviour change.
