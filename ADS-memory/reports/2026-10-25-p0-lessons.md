# What P0 taught us (2026-10-25), carried into P1/P2 briefs

## Process (how Codex runs went)
1. **"Fixed but not rerun" is the norm.** Five of ten build runs fixed a typecheck error and never reran it. The coordinator always reruns. Briefs now allow one re-run after a fix.
2. **Lane lists miss implementers of a changed port.** P2c changed the jobs store interface but its lane omitted `memory-transactions.ts`, and the measure bridge was left unassigned. Rule: when a plan changes a port or interface, it must list EVERY adapter that implements it (memory, SQL, transactional wrappers) and every caller.
3. **Parallel lanes break each other at composition.** QW2 removed policy's unused `ids` dependency, and the server composition (outside its lane) broke until QW3 fixed it. Rule: removing a factory dependency must list its composition call sites, and the lanes must be ordered or the fix pre-authorized.
4. **Test fixtures outside the lane break on contract changes.** Launch v2 broke two campaign fixtures; approver identity broke an audit fixture. Rule: plans grep `tests/` for the changed types and include those fixtures.
5. **Code review catches real bugs.** The P2c review found an expired-lease dispatch bug and complexity violations that the typecheck missed. Keep the Codex code review for every safety-critical run (P1 is full of them).
6. **Line caps work.** P0-1 was planned at ~600 source lines and landed at ~250 after review; P2c at 500–650 landed at ~380. Keep explicit caps in every review.
7. **Never run a non-frozen `pnpm install`.** Adding one workspace dependency made pnpm re-resolve `@mcp-ui/client`'s MCP SDK peer (zod 3 → 4), a silent chat-UI risk. Do it this way: hand-edit the importer block in `pnpm-lock.yaml`, then run `corepack pnpm install --offline --frozen-lockfile`.
8. **Integrator chores recur:** package.json deps, the lockfile, the `development/scripts/boundaries.mjs` allowlist, root scripts. Do them BEFORE dispatching the build that needs them.
9. **Load:** each Codex instance spawns MCP servers unless it runs with `--ignore-user-config` (now in run-phase-retry.sh). Run at most ~4 in parallel. Don't run tests at load >10.

## Product and architecture (feeds P1/P2)
1. **Contracts first works.** Plugins can only import `packages/contracts`, so every P1 capability schema must exist there before plugin work. report.metrics.v1, campaign.status.v1 and tracking.tag.v1 are frozen; campaign.validate.v1, brand.extract.v1 and organic.publish.v1 are IDs only and need schemas in P2.
2. **Money is integer micros:** a decimal string on the wire, BigInt inside. Each P1 plugin must convert vendor units exactly: Google `cost_micros` is already micros (int64); Meta and others return decimal strings in account currency. No floats.
3. **Launch v2 left known gaps for P2:** Meta and LinkedIn return `not_implemented` until destination URLs can be verified, and TikTok requires an exact landing-URL match. P2's launch translation must close these.
4. **Apple reporting is `not_implemented`** until Apple's date-range and finality semantics are confirmed; it is excluded from the P1 reconciliation gate.
5. **The plugin invoker is still a hard-coded 5-plugin list** (`agent-plugin-backends.ts`). P1-2 (manifest-driven `invokeCapability`) must land before the other 12 ad plugins can be wired.
6. **The consent barrier is single-process.** The subject lane is in-memory, which is fine for the local server. A multi-process or cloud server would need a durable lane; record that before any hosted mode.
7. **Approver identity uses the `local_token` fallback** until Jini user-management supports instance-injected permission catalogs (upstream ask pending).
8. **Known plugin debt before wiring:** x-ads (`oauth-1.0a`) and amazon-ses (`@jini-ai/platform`) are missing dependencies. Fix them with the frozen-lockfile method above.
9. **The results UI stays gated** on the real-account reconciliation: Google and Meta spend within ±1%, and a test lead lands on the right CampaignKey. This needs the owner's accounts.
