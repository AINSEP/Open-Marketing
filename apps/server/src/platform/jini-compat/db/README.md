# Server-owned SQLite / Jini compatibility shim

The server owns **better-sqlite3 13.0.3**. All active PGlite/pg dependencies have been removed. Feature packages preinstall better-sqlite3 as a test dependency; feature core uses injected ports. No application import or factory opens a database, runs migrations or starts workers.

`src/index.ts` exports the preserved `PgQueryable`, `PgPool`, `PgClient`, `QueryResult` and typed `PgFoundationError` compatibility names plus `createCheckedSqliteClient({ database })` and `createSqlitePool({ database, kernel })`. The server composition root explicitly constructs/owns the native handle and injects it; the shim does not construct dependencies. Published `@jini-ai/db` **0.3.2**, with **kysely 0.29.6**, now owns SQLite transaction control behind the preserved OM contract. The remaining shim translates query/session shapes and errors; it is removable.

```ts
import { sqliteKernel } from '@jini-ai/db/kernel/sqlite';

// Construct exactly once in server composition; reuse this kernel in Jini SQL repositories.
const checkedClient = createCheckedSqliteClient({ database });
const kernel = sqliteKernel(checkedClient);
const pool = createSqlitePool({ database, kernel });
const result = await withTransaction({
  pool,
  work: tx => tx.query({ text: 'SELECT $1 AS amount', values: [42n] }),
}, { observer });
```

Queries bind PostgreSQL-shaped `$n` parameters by name, including repeated parameters, without rewriting SQL/literals. Both OM queries and the checked client supplied to Jini use `safeIntegers(true)`; the bridge decodes integers to numbers only within JavaScript’s safe range and throws typed `unsafe_integer` otherwise. Strings, blobs, nulls and REAL values survive unchanged. The checked client covers Kysely all/iterate reads and write-result integers too. No active column needs bigint output. Composition must inject the same checked kernel and native handle; constructing another kernel over the raw handle would bypass the checked decoder. The checked client and kernel do not close the server-owned handle. Trusted migration scripts explicitly set `script:true` and use native `exec`, including leading comments and multiple statements; bound values are rejected. Ordinary queries use `prepare`, with no keyword guessing. Query errors retain native causes only for the trusted server boundary. Transaction telemetry never emits SQL, parameters or native error contents.

The pool implements the pure `UnitOfWork` contract from `@open-marketing/contracts`. Use `pool.transaction({ work: ({ session }) => ... })`, passing that session to participating repositories. Root work rolls back on a throw or returned `{ok:false}`; after successful cleanup the original failed Outcome is returned. `session.transaction` joins the same transaction, and the outer caller decides how to handle a nested failure. Both session entry points reject use after release. SQLite transaction statements come only from the injected Jini kernel, which uses `BEGIN IMMEDIATE`. The shim delegates to `kernel.transaction`, converting a returned denial to a private rollback signal and restoring it only after successful rollback. It preserves cleanup causes, quarantine/uncertain-commit behavior and never automatically retries. One native handle is exclusively leased across awaited bodies. An overlapping OM connection request, including a new pool request inside an already-open native transaction, fails with typed `connection_busy` before it can share the transaction; j01 owns scheduling/backpressure or multiple-handle coordination. Destroyed/uncertain leases quarantine the pool, and the composition root must reconcile before replacing/closing it. Pass the request-bound `session` to nested OM repositories; nested Jini repositories use the injected kernel and join its async transaction context. Standalone OM queries use `kernel.run` so they cannot bypass Jini scheduling. Do not retain clients, launch unawaited work or issue transaction control inside a body. After an uncertain outcome composition must stop every consumer of the shared kernel until reconciliation; pool quarantine alone is not a global dispatch barrier.

better-sqlite3 is synchronous: this shim cannot enforce PostgreSQL statement deadlines. Non-default per-transaction timeout overrides fail with `unsupported_timeout`; configure native `busy_timeout` at composition and bound SQL/transaction bodies. The retained Postgres-shaped pool fallback still supports its transaction-local timeout query; no PostgreSQL driver is installed.

Migration bookkeeping uses portable `om_schema_migrations`, integer versions, SHA-256 checksums and text timestamps. Server composition owns the fixed twelve-entry `migrationManifest` and `loadMigrations({ readSql })`; SQL loading is injected and no migration starts automatically. Entries append in global order with a unique feature/local identity. Workspaces 0001 enforces globally unique workspace IDs; provisioning uses `createWorkspaceRecord({ ownerId, ids })` with an injected UUID source. Complete migration sets are limited to 1000 migrations, 1 MiB each and 16 MiB total. History must match an ordered prefix; earlier DDL and ledger inserts roll back together if later SQL fails. SQLite serializes migration writers with `BEGIN IMMEDIATE`; a future Postgres adapter must supply equivalent serialization.


`migrations/0001_spine.sql` is byte-preserved **never-applied historical evidence**, not the SQLite product schema or an automatic startup migration. The owner authorizes reorganizing it; feature jobs own their new tables. No live migration was applied in j00 or j00-finish. Tests apply only throwaway fixture migrations to `:memory:` databases.

The server declares `@jini-ai/db@0.3.2`, `kysely@0.29.6` and spike-only CMS `0.5.6` directly. No pg/PGlite peer or HTTP Kit consumer is added. Run 2 owns the real forms/jobs spike and the forms migration; this run makes no claim of demonstrated A1 compatibility. Integration adapters still need to translate audit/jobs/safety `execute` callbacks, jobs/safety `{sql,parameters}`, workspace `run(session)`, measure `work(transaction)`, and creative positional/rows-only shapes to `{work: ({session})}` and `{text,values}`. Credentials, campaigns and media-library already match the query shape and need the owning session injected.
