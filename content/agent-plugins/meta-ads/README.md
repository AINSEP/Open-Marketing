# Meta Ads plugin

Server-side Meta campaign codecs, strict hierarchy/cap readback, stop-only mapping, exact spend-report normalization and a typed CAPI backend. The plugin stays **disabled and unadmitted**. [Open evidence facts](io.github.ainsep.openmarketing/evidence/README.md) are the first adoption gate; actual hosted tools and schemas remain unavailable.

No vendor tool, credential or MCP configuration is exported to the agent. `mcp.json` has no servers. Portable format follows [Agent Plugins 1.1.0](https://github.com/agentplugins/agent-plugins-spec/blob/main/spec/1.1.0.md); OM declarations and implementation live in `io.github.ainsep.openmarketing`. Portable capability fingerprints identify proposed local codec bytes; the trusted host replaces them with captured schemas/installed digest at admission.

## Server integration

The public source entry is `io.github.ainsep.openmarketing/src/index.ts`. Its factories are inert and take injected ports:

- `createMetaAdsAdapter`: trusted evidence lookup, local bounded JSON-schema validation, server federation gateway, clock and redacted observer. It constructs proposed vendor arguments and `EffectEnvelope`. `createHostedMetaGateway` adapts j10's public federation host, whose trusted catalog resolves effects and enforces exact confirmation at egress. Configure both to the same timeout. j10 reuses published Jini MCP 0.4.3 transport; this plugin starts no second MCP lifecycle.
- `decodeMetaHierarchy`: checks all expected entity IDs/accounts and claims paused only for complete configured PAUSED status. `decodeMetaLimit` requires exact readback and preserves cumulative-cap/average-budget semantics. These codecs do not issue daily hard-limit evidence.
- `mapMetaHaltStop`: converts a safety-issued permit and stop-only effect into PAUSED payloads. The server owns current halt/account/entity validation and actual backend dispatch. This mapping is never exposed as arbitrary MCP updater authority.
- `createMetaCapiBackend`: typed backend capability requiring a durable delivery ID, pinned Graph version/dataset, server-only mode, current consent/admission fence and guarded credentialed egress. It sends one signup/trial website event. The egress port rechecks the fence after credential resolution, bounds timeout/buffers and avoids redirects/retries. Reconciliation remains unknown because no current per-event readback is verified. Server composition must adapt measure's open definition IDs and grants to this plugin's existing signup/trial contract.
- `decodeMetaSpendSnapshot`: returns the public measure snapshot shape after exact account, verified currency exponent, timezone, inclusive-date/half-open-period and precision checks. The caller owns snapshot IDs, immutable persistence, restatement lineage and OM attribution/CAC.

The caller owns generic feature adapters and the single jobs outbox. There are no static feature imports, extra stores, timers or dependency construction here. Call feature adapters through their `@open-marketing/<name>` entries from the server composition root. The narrow creation codec creates one hierarchy entity per operation; full plan composition, targeting/creative upload and all required actual tool fields need host integration and verified schema adaptation.

## Contacts and CAPI handoff

OM contacts is the **only normalizer/hasher**. Supply lowercase 64-character SHA-256 digests in `event.identifiers.email`, `phone` and `external_id`. `mapMetaIdentifiers({ input })` validates them and maps them unchanged to Meta `em`, `ph` and `external_id` arrays. Raw or malformed values reject the whole request; there is no compatibility export named `normalizeMetaIdentifiers` and no plugin fallback hasher.

Optional `fbclid` and `click_time_ms` are paired strings. The click ID is bounded to 220 characters; milliseconds must be a nonnegative safe integer no later than the conversion occurrence. The plugin assembles `fbc = fb.1.<click_time_ms>.<fbclid>` from the captured click time. It preserves a supplied `fbc` and rejects disagreement with derived attribution. It never substitutes dispatch time. IP, user agent, `fbp` and `fbc` remain consent-controlled, unhashed wire fields.

Backend callers may supply `test: { eventCode: "TEST123" }` and server-approved `consent: { opt_out: false, data_processing_options: ["LDU"], data_processing_options_country: 0, data_processing_options_state: 0 }`. A present test object requires a nonblank code. The code becomes root `test_event_code`; consent fields go on the event, preserving explicit false/zero/empty options and adding no defaults. These fields never grant delivery permission. The server authority receives both the original event and the complete `payload`; it must check consent for original identifier keys and assembled attribution, approve metadata, and bind the exact payload to `deliveryId` in existing durable jobs/audit before calling `execute`. Missing current consent returns `forbidden`; missing Graph-version/dataset admission returns `unavailable` before egress, including for test events.

`event_id` is always the shared OM `eventId`, for browser/server vendor deduplication with the same event name. `deliveryId` becomes the stable egress `operationId`; measure/jobs own durable duplicate suppression and the single outbox. Transport loss or ambiguous acknowledgement returns `unknown`. Reconciliation does not resend.

Campaign creation remains an explicit PAUSED write without spending fields. Creation never activates automatically. Activation is a separate exact-card operation with current server authority and independently verified activation binding. A creation acknowledgement does not prove observed PAUSED; complete verified hierarchy readback is required.

Meta's [CAPI parameter docs](https://developers.facebook.com/docs/marketing-api/conversions-api/parameters), [campaign reference](https://developers.facebook.com/docs/marketing-api/reference/ad-campaign-group) and attribution docs returned HTTP 429 on 2026-10-13; hosted documentation was also unreadable. Reachable [Meta SDK request](https://github.com/facebook/facebook-nodejs-business-sdk/blob/main/src/objects/serverside/event-request.js), [event](https://github.com/facebook/facebook-nodejs-business-sdk/blob/main/src/objects/serverside/server-event.js), [campaign](https://github.com/facebook/facebook-python-business-sdk/blob/main/facebook_business/adobjects/campaign.py) and [WooCommerce attribution source](https://github.com/facebook/facebook-for-woocommerce/blob/main/facebook-commerce-pixel-event.php) support wire-model fields and cookie assembly, without certifying hosted behavior, account eligibility or current consent semantics. Details and failed checks are retained in `evidence/primary-sources.json`.
