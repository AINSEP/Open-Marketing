# LINE Ads — R1 reads/auth

Provides `list_accounts`, `list_campaigns`, and campaign-level `report` pages through the sole public `io.github.ainsep.openmarketing/src/index.ts` entry. Disabled and unadmitted by default; server/catalog integration is deferred, so these tools are not yet usable in OM's assistant, HTTP or CLI. No writes, deployment, conversions or OAuth are advertised.

An existing entitled corporate connection supplies a JSON bundle `{ "accessKey": "...", "secretKey": "...", "groupId": "..." }` through OM's existing secure paste-token ingress, never chat. The server credential broker returns that sealed bundle as `accessToken`; only this server-loaded plugin parses it and signs each request. No signature is stored or returned.

The integrator calls `createLineAdsAdapter({ admitted, configuration, credentials, fetch: guardedFetch, clock, createDeadline, observer })`, then `adapter.invoke({ context, operationId, command: { kind: "list_campaigns" } })`. The host supplies `createDeadline: ({ timeoutMs }) => AbortSignal.timeout(timeoutMs)`; the adapter always requests 15000ms, while fixtures supply controlled signals without real timers. Admission must remain live; guarded fetch must recheck current server policy, connection/account ownership and plugin revision immediately before network access. The plugin rechecks admission and binding after credential resolution and before fetch. An unadmitted adapter never accesses credentials or the network.

`configuration` contains server-owned scope, connectionId, accountId, country, currency and timezone. `accountId:null` is allowed only for `list_accounts`; its group comes exclusively from authenticated credentials. Japan connections permit reads only. Taiwan/Thailand bindings return unavailable even when admitted until current regional evidence is recorded. Account discovery may return their metadata; this does not enable account operations.

Every command accepts `page` (1–10000, default 1) and `size` (1–100, default 100). One GET per invocation, fixed `https://ads.line.me/api/v3`, no redirects/retries, 64KiB invocation cap, 1MiB streamed response cap, 15s HTTP deadline. Invalid pages reject atomically. Pagination must match the request and observed count; inconsistent/missing pagination fails closed. Vendor links are never followed. At page 10000, `pageLimitReached` explicitly reports remaining data.

`report` additionally requires valid calendar `since`/`until` strings, ordered and at most 366 days apart. Dates retain vendor semantics and account timezone; no UTC or end-date inclusivity is invented. Response dates must match. Results retain source, API version, retrieval time, currency, account, vendor dates and `coverage:page_only`. Missing metrics are null. Cost remains the vendor numeric observation, without claims of decimal precision, billing finality or account totals. Empty reports mean data/access unconfirmed. Foreign-account or conflicting-currency rows reject the whole page.
